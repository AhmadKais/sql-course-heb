## 1. ברוכים הבאים

אם הגעתם לכאן, כנראה אחד משלושה דברים נכון לגביכם:

- אתם **תלמידי מגמת תקשוב** ובסיסי נתונים הם חלק מהתכנית שלכם
- אתם **רוצים להיכנס לעולם הנתונים** — אנליסט, מפתח, DBA — ושמעתם ש‑SQL היא נקודת הכניסה
- מישהו אמר לכם ש**SQL זו מיומנות ששווה כסף**, ורציתם לבדוק

<div align="center">

**כל השלושה נכונים. וכולם יקבלו את מה שהם צריכים כאן.**

</div>

הקורס הזה בנוי על **תכנית הלימודים של משרד החינוך** לבסיסי נתונים במגמת תקשוב — 32 פרקים, מהמושג "נתון" ועד ניהול טרנזקציות. אבל הוא לא מסתפק בראשי הפרקים: כל נושא מוסבר במלואו, עם דוגמאות, עם סיפורים אמיתיים ממערכות שנפלו, ועם תרגילים שיש להם פתרונות מלאים.

**מה שאין כאן:** קיצורי דרך. **מה שיש כאן:** הכל, לפי הסדר.

## 3. מה זה בעצם בסיס נתונים — בשלוש דקות

נסביר לעומק במודול 1. הנה הגרסה המהירה.

### הבעיה

לדוד יש פיצרייה. בהתחלה הוא רשם הזמנות **בפנקס**:

</div>

```text
   ┌─────────────────────────────────────────┐
   │  יוסי - 050-1234567 - מרגריטה - 45 ש"ח │
   │  דנה - 052-7654321 - פטריות - 52 ש"ח   │
   │  יוסי - 050-1234567 - מרגריטה - 45 ש"ח │
   │  יוסי - 050-1234568 - פפרוני - 48 ש"ח  │  ← טעות הקלדה?
   │  ...                                    │     אותו יוסי או אחר?
   └─────────────────────────────────────────┘
```

<div dir="rtl">

**אחרי חודש דוד רצה לדעת:** מי הלקוחות הקבועים שלי? איזו פיצה הכי נמכרת ביום שלישי? כמה הכנסתי בחודש שעבר?

עם פנקס — הוא צריך לשבת שעות ולספור. ואם יש טעות הקלדה במספר טלפון, יוסי הופך לשני אנשים שונים.

### הפתרון

**בסיס נתונים** מארגן את אותו מידע ב**טבלאות** קשורות:

</div>

```text
   טבלת CUSTOMERS                      טבלת ORDERS
   ┌────┬──────┬─────────────┐         ┌────┬─────────┬────────────┬───────┐
   │ id │ שם   │ טלפון       │         │ id │ cust_id │ תאריך      │ סכום  │
   ├────┼──────┼─────────────┤         ├────┼─────────┼────────────┼───────┤
   │ 1  │ יוסי │ 050-1234567 │◄───┐    │ 101│    1    │ 2026-03-01 │  45   │
   │ 2  │ דנה  │ 052-7654321 │◄─┐ │    │ 102│    2    │ 2026-03-01 │  52   │
   └────┴──────┴─────────────┘  │ └────│ 103│    1    │ 2026-03-04 │  45   │
                                └──────│ 104│    2    │ 2026-03-07 │  48   │
    יוסי נשמר פעם אחת            הקישור└────┴─────────┴────────────┴───────┘
```

<div dir="rtl">

ועכשיו, השאלה של דוד "מי הלקוחות הקבועים שלי?" הופכת ל**שורה אחת**:

</div>

```sql
SELECT c.name, COUNT(*) AS orders
FROM   customers c
JOIN   orders o ON o.cust_id = c.id
GROUP  BY c.name
HAVING COUNT(*) >= 5
ORDER  BY orders DESC;
```

<div dir="rtl">

<div align="center">

**שעות של ספירה ידנית ⟵ שברירי שנייה.**
**זה ההבדל. וזה כל הקורס בתמונה אחת.**

</div>

> 💭 אם השאילתה למעלה נראית לכם כמו ג'יבריש — **מצוין.** זה בדיוק מה שאתם עומדים ללמוד לקרוא, ואז לכתוב. עד סוף הקורס היא תיראה לכם טריוויאלית.

## 4. למה SQL — ולמה דווקא עכשיו

### 4.1 השפה בת ה‑50 שלא מתה

SQL נולדה ב‑1974 במעבדות IBM. מאז נולדו ומתו עשרות שפות תכנות אופנתיות.

**SQL עדיין כאן**, והיא בין המיומנויות **המבוקשות ביותר** בשוק העבודה.

**למה היא לא מתה?**

| הסיבה | ההסבר |
|--------|--------|
| **היא לא שפת תכנות — היא שפת שאלות** | אתם אומרים *מה* אתם רוצים, לא *איך* להשיג |
| **הנתונים לא הולכים לשום מקום** | כל ארגון בעולם צריך לשמור נתונים ולשאול אותם שאלות |
| **AI רק הגדיל את הביקוש** | מודלים לומדים מנתונים. הנתונים יושבים בבסיסי נתונים. מישהו צריך להוציא אותם |
| **היא תקן** | מה שתלמדו כאן יעבוד באורקל, ב‑MySQL, ב‑PostgreSQL ובענן |

### 4.2 מי מרוויח מזה, ואיך

| התפקיד | מה עושים ביום‑יום | כמה SQL צריך |
|---------|---------------------|---------------|
| **Data Analyst** (אנליסט נתונים) | שאילתות, דוחות, דשבורדים, מענה על שאלות עסקיות | 🔴 **הכלי המרכזי** |
| **Data Engineer** | בניית צינורות נתונים, שילוב מקורות, ETL | 🔴 קריטי |
| **מפתח Backend** | כתיבת השרת שמדבר עם בסיס הנתונים | 🔴 קריטי |
| **DBA** (מנהל בסיס נתונים) | ביצועים, גיבויים, אבטחה, זמינות | 🔴 קריטי |
| **מעצב בסיסי נתונים** | תכנון המודל — **בדיוק מה שנעשה במודולים 1–12** | 🔴 קריטי |
| **Data Scientist** | מודלים סטטיסטיים, ML | 🟠 חשוב מאוד |
| **מנהל מוצר / אנליסט עסקי** | לשאול שאלות בעצמם במקום לחכות לאנליסט | 🟡 יתרון גדול |
| **בודק תוכנה (QA)** | אימות נתונים מול הממשק | 🟡 יתרון |

> 💡 **התובנה שלא אומרים מספיק:** SQL היא אחת המיומנויות הבודדות שאפשר ללמוד ביסודיות תוך חודשים ספורים ולהתחיל להשתמש בה **מיד**. אין צורך בתואר, בשלוש שפות תכנות, או בשנתיים ניסיון. יש צורך בהבנה — וזה מה שנבנה כאן.

### 4.3 ומה עם ההסמכה?

תכנית הלימודים מסתיימת (פרק 32) בהכנה ל**בחינת הסמכה של אורקל**. הקורס הזה מכסה את החומר הנדרש, וההסמכה היא תעודה בינלאומית מוכרת.

## 5. מה תדעו לעשות בסוף הקורס

לא "תכירו" ולא "תיחשפו ל". **תדעו לעשות:**

| ✅ | היכולת |
|---|---------|
| ☐ | לשבת מול בעל עסק, לראיין אותו, ולהבין **מה** המערכת שלו צריכה לעשות |
| ☐ | להפוך תיאור מילולי ל**מודל נתונים** מלא — ישויות, מאפיינים, יחסים |
| ☐ | לשרטט **תרשים ERD** מקצועי ולהציג אותו ללקוח שאינו טכני |
| ☐ | לזהות ולתקן **בעיות עיצוב** במודל של מישהו אחר |
| ☐ | **לנרמל** מבנה נתונים עד לצורה השלישית ולהסביר למה |
| ☐ | לתרגם מודל ל**טבלאות אמיתיות** — `CREATE TABLE` עם מפתחות ואילוצים |
| ☐ | לכתוב **שאילתות SELECT** — מהפשוטות ועד למורכבות |
| ☐ | לחבר **מספר טבלאות** בכל סוגי ה‑JOIN |
| ☐ | להשתמש ב**פונקציות** — טקסט, מספרים, תאריכים, המרות ותנאים |
| ☐ | **לקבץ ולסכם** נתונים — `GROUP BY`, `HAVING`, שאילתות מקוננות |
| ☐ | **לעדכן, להוסיף ולמחוק** נתונים בבטחה |
| ☐ | ליצור **Views, אינדקסים, רצפים** ולנהל **הרשאות** |
| ☐ | לנהל **טרנזקציות** ולהבין למה הכסף שלכם לא נעלם בהעברה בנקאית |

### ❓ "רגע — למה 15 פרקים לפני שכותבים SQL בכלל?"

זו השאלה הכי נפוצה, והיא הוגנת. הנה התשובה:

<div align="center">

**כי SQL היא הקלה. העיצוב הוא הקשה.**

</div>

לכתוב `SELECT` תלמדו בשבוע. **לדעת איזה טבלאות בכלל צריכות להיות שם** — זה מה שמפריד בין מי שמריץ שאילתות למי שבונה מערכות.

וחשוב מזה: **מבנה נתונים גרוע לא ניתן לתקן בשאילתות.** אם הטבלאות בנויות לא נכון, אתם תבזבזו את שארית הקריירה שלכם בכתיבת שאילתות מפותלות שמנסות לפצות על זה.

## 10. חמש טעויות שעושים בקורס הזה

> 🎬 **הטעויות האלה נאספו מלומדים אמיתיים. אל תעשו אותן.**

### ❌ טעות 1 — לדלג על הסיפורים

הקופסאות `🎬 סיפור מהשטח` נראות כמו קישוט. **הן לא.** כל אחת מהן מסבירה **למה** מושג תיאורטי קיים — ומושג שאתם מבינים למה הוא קיים, אתם לא שוכחים.

> ✅ **מה לעשות במקום:** אם סעיף תיאורטי לא מתחבר — קראו קודם את הסיפור שלידו, ואז חזרו.

### ❌ טעות 2 — "אני אקרא עכשיו ואתרגל אחר כך"

"אחר כך" לא מגיע. וכשהוא מגיע, שכחתם את החומר וצריך לקרוא מחדש.

> ✅ **מה לעשות במקום:** מודול = ארבעת הקבצים. מודול שקראתם בלי לתרגל — **לא סיימתם**.

### ❌ טעות 3 — לרוץ ל‑SQL ולדלג על העיצוב

זו הטעות היקרה ביותר. אתם תדעו לכתוב שאילתות, ולא תדעו לבנות מערכת.

> ✅ **מה לעשות במקום:** הסדר של תכנית הלימודים אינו שרירותי.

### ❌ טעות 4 — להעתיק את הפתרון ולהמשיך

ראו סעיף 7.3. אשליית הבהירות היא אויב אמיתי.

> ✅ **מה לעשות במקום:** אם ניסיתם ולא הצלחתם — קראו את **תחילת** הפתרון בלבד, סגרו, ונסו שוב.

### ❌ טעות 5 — ללמוד לבד לגמרי

עיצוב נתונים הוא מקצוע של **דיון**. שני אנשים שמסתכלים על אותו מודל יראו דברים שונים.

> ✅ **מה לעשות במקום:** מצאו שותף ללמידה, או **הסבירו את המודל שלכם בקול רם** — גם לקיר. אם אתם לא מצליחים להסביר יחס במשפט תקין, הוא כנראה שגוי. (זו לא בדיחה — זו טכניקת בדיקה רשמית שנלמד במודול 3.)

## 11. הפרויקט המלווה 🐾

לאורך כל הקורס נבנה יחד מערכת **אחת אמיתית**: מקלט לבעלי חיים.

בכל מודול, **התרגיל האחרון** מוסיף לה שכבה:

</div>

```text
   מודול 2  →  מי הישויות? מה המאפיינים? מה נשאל את הלקוחה?
```

## 12. שאלות נפוצות

<details><summary><b>❓ אני לא יודע שום דבר בתכנות. זה מתאים לי?</b></summary>

**כן.** SQL אינה שפת תכנות במובן הרגיל — אין בה לולאות, אין משתנים, ואין אלגוריתמים. היא שפה **הצהרתית**: אתם מתארים *מה* אתם רוצים לקבל, ובסיס הנתונים מחליט *איך* להשיג את זה.

מודולים 1–11 בכלל אינם דורשים מחשב.

</details>

<details><summary><b>❓ כמה זמן עד שאדע לכתוב שאילתה אמיתית?</b></summary>

שאילתה ראשונה — **מודול 13**. שאילתות מורכבות באמת (JOIN, GROUP BY, תת‑שאילתות) — מודולים 21–24.

בקצב סטנדרטי של 2 מודולים בשבוע: כחודשיים עד השאילתה הראשונה, כשלושה וחצי עד שליטה.

</details>

<details><summary><b>❓ אני חייב לעשות את כל התרגילים?</b></summary>

**את ה‑🟢 וה‑🟡 — כן.** את ה‑🔴 — מומלץ מאוד, אבל אם הזמן לוחץ, אפשר לבחור.

**חוץ מהתרגיל האחרון בכל מודול** (הפרויקט) — אותו עשו תמיד. הוא זה שמחבר הכל.

</details>

<details><summary><b>❓ אני לומד לבגרות במגמת תקשוב. הקורס מכסה את החומר?</b></summary>

הקורס בנוי **ישירות** על תכנית הלימודים של משרד החינוך — כל 32 הפרקים, לפי הסדר, כולל הפרויקט המלווה מפרק 9 והכנה להסמכה מפרק 32.

הוא גם **מרחיב** מעבר לראשי הפרקים, כי ראשי פרקים לא מלמדים.

👈 [מיפוי מלא של הפרקים](../../SYLLABUS.md)

</details>

<details><summary><b>❓ למדתי SQL קצת. אפשר לדלג?</b></summary>

בדקו את עצמכם עם [שאלות מודול 5](../module-05-relationships/questions.md). אם אתם עונים בביטחון על שאלות 11–14 (מזהה ישות מקשרת, M:M רקורסיבי, יחס טרנרי) — דלגו לחלק ב'.

אם לא — התחילו מההתחלה. רוב מי ש"למד SQL קצת" מכיר `SELECT` ולא מכיר עיצוב, וזה בדיוק החלק שקובע.

</details>

<details><summary><b>❓ מה ההבדל בין SQL לבין MySQL / Oracle / PostgreSQL?</b></summary>

**SQL** היא ה**שפה** (כמו "עברית").
**MySQL, Oracle, PostgreSQL, SQL Server** הם **מוצרים** שמדברים אותה (כמו עיתונים שונים בעברית).

התחביר כמעט זהה בכולם. יש הבדלים בפונקציות מסוימות — נציין אותם כשנגיע.

</details>

<details><summary><b>❓ נתקעתי. מה עושים?</b></summary>

1. **חזרו לסעיף הרלוונטי** בהסבר — לרוב התשובה שם
2. **בדקו ב[מילון המונחים](../../resources/glossary.md)** — אולי זה מונח שלא התיישב
3. **קראו את הסיפור** בקופסה הקרובה — הוא מסביר את ה"למה"
4. **הסבירו את הבעיה בקול רם** — חצי מהפעמים תפתרו אותה תוך כדי
5. **המשיכו הלאה וחזרו מחר** — המוח ממשיך לעבד ברקע

</details>

<details><summary><b>❓ יש בחינות או תעודה?</b></summary>

בקורס עצמו — שאלות הבדיקה העצמית והתרגילים הם ההערכה.

מעבר לזה: תלמידי מגמת תקשוב ניגשים ל**בגרות**, ופרק 32 מכין ל**הסמכת אורקל** — תעודה בינלאומית מוכרת.

</details>

<details><summary><b>❓ למה הכל בעברית? לא עדיף ללמוד באנגלית?</b></summary>

**המושגים** נלמדים טוב יותר בשפת האם. **המונחים** נלמדים באנגלית — וכך תמצאו אותם כאן: כל מונח מופיע בשתי השפות, ויש [מילון](../../resources/glossary.md) מלא.

כשתגיעו לתיעוד של אורקל, המונחים כבר יהיו מוכרים.

</details>
