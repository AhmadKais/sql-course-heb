## 🟡 תרגיל 4 — פרקו לטיפוסי משנה

חברת נדל"ן מנהלת נכסים. לפניכם טבלה שטוחה. **פרקו אותה לטיפוס על וטיפוסי משנה.**

</div>

```text
┌───────────────────────────────────────────────────────────────┐
│                          PROPERTY                             │
├───────────────────────────────────────────────────────────────┤
│ # property_id        │ * price            │ o num_of_rooms    │
│ * property_type      │ * city             │ o floor           │
│ * address            │ * street           │ o has_elevator    │
│ * size_sqm           │ * listing_date     │ o has_parking     │
│ * agent_id           │ * status           │ o land_size_sqm   │
│                      │                    │ o num_of_floors   │
│                      │                    │ o has_garden      │
│                      │                    │ o office_rooms    │
│                      │                    │ o has_reception   │
│                      │                    │ o zoning_type     │
│                      │                    │ o warehouse_height│
│                      │                    │ o loading_docks   │
└───────────────────────────────────────────────────────────────┘

    property_type ∈ { דירה, בית פרטי, משרד, מחסן, מגרש }
```

<div dir="rtl">

**המשימות:**

**א.** זהו את המאפיינים **המשותפים** ⟵ טיפוס העל.
**ב.** קבצו את המאפיינים הייחודיים ⟵ טיפוסי המשנה.
**ג.** בדקו את **שני הכללים**. האם צריך `OTHER`?
**ד.** שרטטו את המודל המלא.
**ה.** האם **מגרש** צריך טיפוס משנה משלו? הוא כמעט חסר מאפיינים ייחודיים — הכריעו ונמקו.
**ו.** הציעו **שיטת מימוש** (א'/ב'/ג') ונמקו. שימו לב: יש ישות `VIEWING` (ביקור בנכס) שצריכה להצביע על **כל** סוגי הנכסים.

## 🟡 תרגיל 5 — תפקידים במקום טיפוסי משנה

בית ספר עיצב כך:

</div>

```text
    ┌──────────────────────────────────────────────────┐
    │                     PERSON                       │
    │  # person_id · * first_name · * last_name        │
    │  ┌───────────┐ ┌──────────┐ ┌────────┐ ┌───────┐ │
    │  │  STUDENT  │ │ TEACHER  │ │ PARENT │ │ STAFF │ │
    │  ├───────────┤ ├──────────┤ ├────────┤ ├───────┤ │
    │  │*class_id  │ │*subject  │ │*child_ │ │*role  │ │
    │  │*grade_lvl │ │*seniority│ │  id    │ │       │ │
    │  └───────────┘ └──────────┘ └────────┘ └───────┘ │
    └──────────────────────────────────────────────────┘
```

<div dir="rtl">

**המשימות:**

**א.** מצאו **שלושה** תרחישים אמיתיים בבית ספר שמפרים את כלל הבלעדיות.
**ב.** תארו את הנזק הקונקרטי שכל אחד מהם גורם.
**ג.** תכננו מחדש עם ישות `ROLE`. שרטטו.
**ד.** ⚠️ **השאלה הקשה:** במודל התפקידים, איפה נשמור את `grade_level` (שכבה) של תלמיד, ו‑`seniority` (ותק) של מורה? הם רלוונטיים **רק** לתפקיד מסוים. הציעו **שני** פתרונות ובחרו.
**ה.** האם **אחרי** התיקון נשארו טיפוסי משנה לגיטימיים במודל? אילו?

## 🟡 תרגיל 6 — מסמך חוקים עסקיים

לפניכם תיאור של מערכת השכרת ציוד לאירועים:

> *"אנחנו משכירים ציוד לאירועים — הגברה, תאורה, שולחנות, כיסאות. לקוח מזמין ציוד לתאריך מסוים. ציוד יקר (מעל 5,000 ₪) דורש פיקדון של 20%. לא ניתן להשכיר את אותו פריט לשני אירועים באותו תאריך. לקוח חדש חייב לשלם מראש; לקוח ותיק (מעל 3 השכרות) יכול לשלם אחרי. אם ציוד מוחזר פגום — הלקוח מחויב בעלות התיקון. הזמנה שבוטלה פחות מ‑48 שעות לפני האירוע מחויבת ב‑50%. מנהל יכול לוותר על דמי ביטול. לא ניתן למחוק לקוח שיש לו הזמנה עתידית."*

**המשימות:**

**א.** זהו **את כל** החוקים העסקיים (צפו ל‑8–10).
**ב.** לכל חוק — מלאו טבלת תיעוד מלאה (מזהה, תיאור, ישויות, סוג, רמת אכיפה, הפרה, חריגים).
**ג.** סווגו כל חוק לפי רמת אכיפה ①–④.
**ד.** מצאו את החוקים ש**אי אפשר** לאכוף ברמה ①, והסבירו למה.
**ה.** מצאו את החוק שיש לו **חריג מפורש** בתיאור. למה חריגים כאלה מסוכנים אם לא מתועדים?
**ו.** נסחו **שלוש שאלות** ללקוח על חוקים ש"מובנים מאליהם" ולא הוזכרו.

## 🔴 תרגיל 7 — עיצוב מלא: בית חולים

> *"בית החולים מנהל אנשי צוות: רופאים, אחיות וצוות מנהלי. לרופא יש התמחות ומספר רישיון. לאחות יש דרגה והסמכות. לצוות מנהלי יש מחלקה ותפקיד. כל אנשי הצוות מקבלים משכורת ומשובצים למשמרות. מטופלים מתאשפזים במחלקות. יש אשפוז רגיל ואשפוז יום. באשפוז רגיל יש מיטה ומספר ימים; באשפוז יום יש שעת הגעה ושעת שחרור. כל אשפוז מנוהל על ידי רופא אחראי. מטופל יכול לעבור בדיקות — בדיקות דם, הדמיה, ובדיקות תפקוד. לכל סוג בדיקה יש פרמטרים שונים."*

**המשימות:**

**א.** זהו את **כל** טיפוסי העל וטיפוסי המשנה.
**ב.** לכל היררכיה — בדקו את שני הכללים ותקנו במידת הצורך.
**ג.** ⚠️ **מלכודת:** האם רופא שהוא גם מנהל מחלקה שובר את המודל? איך תפתרו?
**ד.** שרטטו את המודל המלא, כולל היחסים בין ההיררכיות.
**ה.** הציעו שיטת מימוש לכל היררכיה בנפרד — ונמקו למה הן עשויות להיות **שונות**.
**ו.** כתבו מסמך חוקים עסקיים עם **לפחות 10 חוקים**, כולל לפחות 3 שאי אפשר לאכוף במבנה.

## 🔴 תרגיל 8 — השוואת שיטות מימוש

עבור המודל:

</div>

```text
   VEHICLE (# vehicle_id, * license_plate, * manufacturer, * year)
      ├─ PRIVATE_CAR  (* num_of_seats, * has_child_seat)
      ├─ TRUCK        (* max_load_tons, * num_of_axles, * license_class)
      └─ MOTORCYCLE   (* engine_cc, * has_sidecar)

   בנוסף קיימות:
   PARKING_TICKET (# ticket_id, * vehicle_id, * date, * amount)
   INSURANCE      (# policy_id, * vehicle_id, * start_date, * premium)
```

<div dir="rtl">

**המשימות:**

**א.** כתבו `CREATE TABLE` מלא לכל אחת משלוש השיטות.

**ב.** לכל שיטה, כתבו את השאילתה: **"כל הרכבים שקיבלו דוח חניה בשנת 2026"**.

**ג.** לכל שיטה, כתבו את השאילתה: **"כל המשאיות עם עומס מעל 10 טון"**.

**ד.** בשיטה ב' — איך תממשו את `PARKING_TICKET`? הראו את הבעיה בקוד.

**ה.** מלאו טבלת השוואה:

| הקריטריון | א' | ב' | ג' |
|-----------|-----|-----|-----|
| מספר טבלאות | | | |
| ערכי NULL | | | |
| אפשר NOT NULL על `max_load_tons`? | | | |
| שאילתה "כל הרכבים" | | | |
| FK מ‑`PARKING_TICKET` | | | |
| הוספת סוג "אוטובוס" | | | |

**ו.** קבעו: איזו שיטה תבחרו **כאן**? נמקו בהתייחסות ל‑`PARKING_TICKET` ו‑`INSURANCE`.

## 🔴 תרגיל 9 — החוק שלא נאמר

<div align="center">

*תרגיל בסגנון "סיפור מהשטח"*

חברת מסחר מקוון השיקה מערכת חדשה. תוך חודש התגלו התקלות הבאות:

| # | התקלה |
|---|--------|
| 1 | לקוח הזמין 500 יחידות של מוצר שיש ממנו 3 במלאי. ההזמנה אושרה |
| 2 | פקידה נתנה הנחה של 95% "בטעות". ההזמנה עברה |
| 3 | לקוח נמחק מהמערכת; 12 מההזמנות שלו הפכו ל"יתומות" ללא לקוח |
| 4 | מוצר נמחק מהקטלוג; דוחות מכירה היסטוריים החלו להציג שורות ריקות |
| 5 | לקוח החזיר מוצר שנקנה לפני 3 שנים וקיבל החזר מלא |
| 6 | שתי הזמנות קיבלו את אותו מספר הזמנה |
| 7 | מוצר נשלח ללקוח לפני שהתשלום התקבל |
| 8 | קופון "חד פעמי" נוצל 47 פעמים על ידי אותו לקוח |

**המשימות:**

**א.** לכל תקלה — נסחו את **החוק העסקי** שהיה מונע אותה.
**ב.** קבעו לכל חוק את **רמת האכיפה** המתאימה (①–④), ונמקו.
**ג.** לחוקים ברמה ① — כתבו את האילוץ בפועל (`CHECK`, `FK`, `UNIQUE`…).
**ד.** לחוקים ברמה ②–③ — תארו את הלוגיקה במילים.
**ה.** ⚠️ תקלה מספר 5 — למה היא **שונה מהותית** מהאחרות? מה זה מלמד על תיעוד חוקים?
**ו.** בנו מסמך חוקים עסקיים מלא לכל שמונת המקרים.

## 🔴 תרגיל 10 — פרויקט: מקלט לבעלי חיים (שלב ג')

> 🐾 השלב האחרון של הפרויקט בארבעת המודולים הראשונים.

**המשימות:**

**א. טיפוסי משנה של `ANIMAL`:**
המקלט קולט כלבים, חתולים, ארנבים ותוכים. לכל מין יש דרישות שונות:
- **כלב:** גזע, גודל, אימון סוגרים, תוקפנות כלפי כלבים אחרים
- **חתול:** האם מעוקר, האם חתול בית או חוץ, FIV/FeLV
- **ארנב:** סוג פרווה, האם מעוקר
- **תוכי:** מין הציפור, האם מדבר, אורך כנף

1. האם זה מקרה לטיפוסי משנה או למאפיינים? נמקו **בכל שלוש הבחינות** (מאפיינים ייחודיים / יחסים ייחודיים / חוקים עסקיים).
2. אם כן — שרטטו את ההיררכיה ובדקו את שני הכללים.
3. איזו שיטת מימוש תבחרו? זכרו: `VET_EXAM`, `ADOPTION` ו‑`EXPENSE` צריכים להצביע על **כל** חיה.

**ב. טיפוסי משנה של `PERSON`:**
במודול 2 הכרענו לטובת ישות `PERSON` אחת עם תפקידים. אבל לווטרינר יש `license_number` ולמתנדב יש `volunteer_start_date` — מאפיינים ייחודיים לתפקיד.

1. איפה נשמור אותם?
2. הציעו **שלושה** פתרונות אפשריים והשוו ביניהם.
3. בחרו והסבירו.

**ג. טיפוסי משנה של `INTAKE`:**
קליטה היא **או** מציאה ברחוב **או** מסירה מבעלים. במודול 3 סימנו זאת כ**קשת**.

1. האם עדיף כאן **קשת** או **טיפוסי משנה**? השוו.
2. אילו מאפיינים ייחודיים יש לכל סוג?
3. הכריעו ונמקו.

**ד. מסמך חוקים עסקיים מלא:**
כתבו מסמך עם **לפחות 15 חוקים** למקלט. חובה לכלול:
- לפחות 4 חוקים ברמה ① (מבנה)
- לפחות 4 חוקים ברמה ② (טריגר)
- לפחות 2 חוקים ברמה ③ (אפליקציה)
- לפחות 2 חוקים ברמה ④ (נוהל אנושי)
- לפחות 3 חוקים עם **חריג מתועד**

**ה. סיכום הפרויקט:**
כתבו מסמך של עמוד אחד למנהלת המקלט, שמסביר **בשפה לא טכנית**:
- מה המערכת תדע לעשות
- שלוש החלטות עיצוב מרכזיות ולמה קיבלתם אותן
- שלוש שאלות פתוחות שעדיין דורשות את החלטתה
