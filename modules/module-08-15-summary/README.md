# תמצית: עבודה מול לקוח, תכנון הפרויקט והגנה עליו

> **מחליף בקורס את פרקים 8, 13, 14 ו‑15** (תפקיד היועץ, SQL I ועבודת צוות, SDLC, המצגת). במקום ארבעה פרקים ארוכים, כאן מופיע רק מה שצריך **בפועל** כדי לבנות את הפרויקט, להגיש את תיק הפרויקט ולהגן עליו.
> הפרקים המלאים נשארו בתיקיית הקורס להרחבה, למי שרוצה.
>
> 🎓 **למה זה חשוב:** בשאלון 735915 (מעבדה, מסדי נתונים SQL), **30%** מהציון הם תיק הפרויקט ו‑**70%** הם ההגנה עליו.

## 1. מהלקוח לטבלאות: חמישה צעדים (פרק 8)

| # | הצעד | מה מקבלים בסוף |
|:-:|------|-----------------|
| 1 | **ראיון** עם הלקוח: מה הוא עושה, מה הוא רוצה לדעת | רשימת שאלות שהמערכת צריכה לענות עליהן |
| 2 | **חוקים עסקיים**: משפטים כמו "לכל חוג מאמן אחד" | 10–20 חוקים כתובים |
| 3 | **ERD / DSD** | טבלאות, מפתחות וקווים |
| 4 | **הצגה ללקוח** במילים שלו ("כל חוג שייך למאמן אחד"), בלי "FK" ובלי "1:N" | אישור או תיקונים |
| 5 | **יומן החלטות**: מה הוחלט, מתי, ולמה | הגנה מפני "אבל ביקשתי אחרת" |

> 💡 **שאלות טובות לראיון:** "מה קורה כש‑...?", "יכול להיות ש‑... יותר מפעם אחת?" (זו שאלה שמגלה קשרי N:M), "מה אתם צריכים לראות בסוף כל חודש?" (ככה מגלים מה השאילתות).

## 2. מחזור החיים של המערכת (SDLC): שבעה שלבים (פרק 14)

</div>

```text
 1 ייזום  ->  2 ניתוח  ->  3 עיצוב  ->  4 בנייה  ->  5 בדיקות  ->  6 הטמעה  ->  7 תחזוקה
            (ראיון,      (ERD,       (CREATE,     (מקרי        (העברה       (תיקונים,
             חוקים)      נרמול)      INSERT)      קצה)         ללקוח)       שינויים)
```

<div dir="rtl">

- **מפל מים (Waterfall):** כל שלב מסתיים לפני שהשלב הבא מתחיל.
- **Agile:** סבבים קצרים. בונים חלק, מראים ללקוח, משפרים.
- **למה בסיס הנתונים מתוכנן מוקדם?** כי לשנות טבלה אחרי שכבר נכנסו נתונים זה יקר: צריך `ALTER`, העברת נתונים ותיקון שאילתות.

**בדיקות לבסיס נתונים: מה בודקים?**

| הבדיקה | דוגמה |
|--------|-------|
| אילוץ עובד | `INSERT` של רשומה בלי שם צריך **להיכשל** |
| מפתח זר עובד | אימוץ של חיה שלא קיימת צריך **להיכשל** |
| שאילתה נכונה | התוצאה זהה למה שספרתם ביד |
| מקרה קצה | NULL, טבלה ריקה, תאריך בסוף החודש |

## 3. עבודת צוות (פרק 13)

- מפרקים את הפרויקט למשימות קטנות: "טבלה + נתונים", "5 שאילתות", "View".
- **לוח Kanban** עם שלוש עמודות: לעשות · בעבודה · גמור.
- כל קוד ה‑SQL נמצא בקובץ אחד, `build.sql`, שבונה **הכול מאפס**: `DROP`, `CREATE`, `INSERT`, ואחר כך השאילתות. אם הקובץ רץ מההתחלה עד הסוף בלי שגיאה, הפרויקט עובד.

## 4. תיק הפרויקט: מה חייב להיות בו

לפי דרישות הגמר של משרד החינוך:

| # | הפרק בתיק | מה כותבים |
|:-:|-----------|-----------|
| 1 | **מבוא** | מה הארגון, ומה הבעיה |
| 2 | **דרישות פונקציונליות** | מה המערכת יודעת לעשות ("להציג את כל החוגים של מאמן") |
| 3 | **מטרות הפרויקט** | 3–5 מטרות |
| 4 | **תרשים ERD / DSD** | עם מפתחות ראשיים, מפתחות זרים וקווי קשר |
| 5 | **פירוט השאילתות** | לכל שאילתה: המטרה, הקוד, צילום של התוצאה, **ואיזה סוג** היא (סינון, צירוף, קיבוץ, תת־שאילתה, DML) |
| 6 | **רכיבים נוספים** | Views (טבלאות מדומות), אינדקסים, הרשאות, ואם נלמדו גם פרוצדורות ו‑Triggers |

> ⚠️ פרויקט שבנוי ב‑Access בלבד **לא** מתקבל. צריך שרת: MySQL או SQL Server.

## 5. ההגנה (70%): איך מתכוננים (פרק 15)

**מבנה של 10 דקות:**
1. **דקה:** מה הארגון ומה הבעיה.
2. **שלוש דקות:** ה‑ERD. מסבירים **שתי החלטות עיצוב** ("למה יש טבלת קישור", "למה העיר נמצאת בטבלה נפרדת").
3. **חמש דקות:** הדגמה חיה. מריצים 4–5 שאילתות, מהפשוטה למורכבת.
4. **דקה:** מה הייתי משפר.

**שאלות שבוחנים שואלים כמעט תמיד, ומה עונים:**

| השאלה | מה עונים |
|-------|----------|
| "מה המפתח הראשי בטבלה הזו, ולמה?" | ייחודי, לא ריק, יציב |
| "איפה יש קשר רבים לרבים?" | מראים את טבלת הקישור ואת המפתח המורכב שלה |
| "מה קורה אם אמחק את הרשומה הזו?" | מסבירים את המפתח הזר: המחיקה תיכשל, או שהרשומות הקשורות יימחקו (CASCADE) |
| "תשנה את השאילתה ככה ש‑..." | מוסיפים `WHERE` / `ORDER BY` / `GROUP BY` **בשידור חי** |
| "למה השתמשת ב‑LEFT JOIN כאן?" | כדי לא לאבד רשומות שאין להן התאמה |
| "מה זה View, ולמה צריך אותו?" | שאילתה שמורה עם שם. היא חוסכת כתיבה ומסתירה עמודות |

> 💡 **תוכנית גיבוי חובה:** צילומי מסך של כל התוצאות, למקרה שהמחשב או הרשת נופלים באמצע ההדגמה.
