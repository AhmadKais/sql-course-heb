## 1. איך המודול הזה עובד

</div>

```text
+------------------------------------------------------------------+
|  This is a DOING module. Reading here is 20%; the work is 80%.   |
+------------------------------------------------------------------+

  README (here)     <- the case file: who the client is, what is asked, how you're graded
  questions.md      <- review exam on modules 1-8 (BEFORE you start!)
  exercises.md      <- the project itself: 6 stages + raw material
  solutions.md      <- full reference solution -- open only at the END

  Recommended time:  8-12 hours of work, spread over one to two weeks.
                     Not in a single evening.
```

### 2.2 מה רותי ביקשה, במילים שלה

> *"אני צריכה משהו שיחזיק את הכול במקום אחד. היום, כשמישהו מתקשר לשאול על כלב שראה באתר — אני צריכה לחפש בשלושה מקומות, ולפעמים אני פשוט לא זוכרת אם הוא כבר מאומץ.*
>
> *ויש עוד משהו. אני חייבת לדעת כמה כל חיה עולה לי. אנחנו מגישים בקשה למענק בשנה הבאה, והם שואלים 'כמה עולה טיפול בחיה אחת בממוצע'. אין לי מושג. אני יודעת כמה שילמתי לווטרינר, אבל לא לפי חיה.*
>
> *ודבר אחרון — אני רוצה שהמתנדבות יוכלו לרשום דברים בעצמן. היום הכול עובר דרכי, ואם אני בחופש, שבוע שלם לא נרשם כלום."*
>
> — **רותי אלמוג**, מנהלת ומייסדת

### 2.3 שלוש שאלות שהמערכת **חייבת** לענות עליהן

תכנית הלימודים מדגישה: מערכת נבנית כדי לענות על שאלות. אלה שלוש שהוגדרו במפורש:

| # | השאלה | למה היא קריטית |
|---|--------|-----------------|
| 1 | **כמה זמן חיה שוהה אצלנו בממוצע?** | מדד ביצוע מרכזי; נדרש בדוח לתורמים |
| 2 | **כמה עולה להחזיק חיה, מקליטה עד אימוץ?** | ⚠️ תנאי לקבלת המענק |
| 3 | **איזו חיה מתאימה למשפחה שמולי?** | הפונקציה היומיומית המרכזית |

> 🔑 **לפני שאתם מציגים מודל — בדקו אותו מול שלוש השאלות האלה.** מודל יפה שלא עונה עליהן הוא מודל שנכשל.

## 4. שישה שלבים

</div>

```text
+---------------------------------------------------------------------+
| STAGE 1 -- READ THE TRANSCRIPT          1 hour                      |
|   Read the client interview twice. The second time -- with a pencil.|
|   Mark every noun. Mark every "usually" and "except".               |
+---------------------------------------------------------------------+
| STAGE 2 -- EXTRACT                      2 hours                     |
|   entities . attributes . relationships . business rules . open qs  |
|   <- four separate lists. No drawing yet.                           |
+---------------------------------------------------------------------+
| STAGE 3 -- BUILD                        3 hours                     |
|   ERD -> normalize -> constraints -> check against the 3 questions  |
|   <- modules 3, 4, 5, 6, 7 -- all together                          |
+---------------------------------------------------------------------+
| STAGE 4 -- PRESENT                      1 hour                      |
|   script + plain-language entity glossary + deliberate mistake      |
|   <- module 8                                                       |
+---------------------------------------------------------------------+
| STAGE 5 -- INCORPORATE CHANGES          2 hours                     |
|   Ruti responds. Some responses break things.                       |
|   <- the part that separates an exercise from a real project        |
+---------------------------------------------------------------------+
| STAGE 6 -- HANDOVER                     1-2 hours                   |
|   the seven documents, organised, so someone else can continue      |
+---------------------------------------------------------------------+
```

## 5. איך תיבדקו — מחוון

</div>

```text
+--------------------------------+--------+------------------------------+
| CRITERION                      | points | WHAT WE LOOK FOR             |
+--------------------------------+--------+------------------------------+
| Model completeness             |  20    | everything in the transcript |
|                                |        | is represented; no entity    |
|                                |        | missing                      |
+--------------------------------+--------+------------------------------+
| Relationship correctness       |  15    | cardinality + optionality    |
|                                |        | right; M:M resolved; arcs OK |
+--------------------------------+--------+------------------------------+
| Normalization                  |  15    | 3NF . no code+description    |
|                                |        | together; historic values    |
|                                |        | in place                     |
+--------------------------------+--------+------------------------------+
| Constraints & business rules   |  15    | 20+ rules . enforcement level|
|                                |        | for each . domains defined   |
+--------------------------------+--------+------------------------------+
| * Answering the three questions|  15    | does the model REALLY answer |
|                                |        | them? Show how               |
+--------------------------------+--------+------------------------------+
| Client communication           |  10    | plain-language glossary .    |
|                                |        | jargon-free script .         |
|                                |        | questions in her language    |
+--------------------------------+--------+------------------------------+
| Incorporating changes          |  10    | (!) did you spot which       |
|                                |        | request BREAKS the model?    |
+--------------------------------+--------+------------------------------+
                                   100
```

<div dir="rtl">

> 💡 **שימו לב שני קריטריונים שווים 25 נקודות ואינם "עיצוב":** המענה לשאלות העסקיות, ושילוב השינויים. זה לא במקרה — **בפרויקט אמיתי, שם נופלים.**

## 6. חמש מלכודות שמפילות פרויקטים כאלה

| # | המלכודת | הסימן | התיקון |
|---|----------|--------|---------|
| 1 | **להתחיל לצייר מיד** | ERD אחרי 10 דקות קריאה | קודם ארבע רשימות, אחר כך תרשים |
| 2 | **לדלג על מה שלא הבנתם** | ישות שלא ברור מה עושים איתה | ⟵ **זו שאלה פתוחה. רשמו אותה** |
| 3 | **לענות רק על מה שנאמר** | מודל שלא עונה על שלוש השאלות | בדקו את המודל מולן לפני ההצגה |
| 4 | **להתאהב במודל** | התנגדות לשינוי שרותי ביקשה | המודל שלה, לא שלכם |
| 5 | **לקבל כל שינוי** | המודל נשבר אחרי שלב 5 | ⚠️ בקשה אחת בשלב 5 **חייבת** להיענות בסירוב מנומק |

> 🎬 **סיפור מהשטח: הפרויקט שהיה מושלם ונכשל**
>
> קבוצת סטודנטים הגישה פרויקט מרשים: 24 ישויות, מנורמל למופת, כל אילוץ במקומו. הציון על העיצוב היה מלא.
>
> בהגנה שאל הבוחן שאלה אחת: *"תראו לי איך אתם עונים על 'כמה עולה להחזיק חיה'."*
>
> שתיקה. הם שמרו `EXPENSE` עם סכום וקטגוריה — אבל **בלי קשר לחיה**. הוצאה על שק מזון נרשמה כהוצאה כללית, ווטרינר חייב את המקלט בחשבונית אחת לחמש חיות.
>
> המודל היה נכון. הוא פשוט **לא ענה על השאלה שבגללה הפרויקט התחיל**.
>
> 🔑 **הלקח:** התחילו מהשאלות ובנו לאחור. לא הפוך.

## 8. סיכום

<div align="center">

### 🧠 חמש נקודות

</div>

1. **מודל נמדד במה שהוא עונה עליו, לא בכמה ישויות יש בו.** שלוש השאלות של רותי הן המבחן האמיתי.
2. **ארבע רשימות לפני תרשים אחד.** ישויות · מאפיינים · יחסים · חוקים. הציור הוא השלב האחרון, לא הראשון.
3. **מה שלא הבנתם הוא שאלה פתוחה, לא בעיה.** מסמך שאלות פתוחות הוא סימן למקצועיות, לא לחוסר ידע.
4. **שילוב שינויים הוא המבחן האמיתי.** מודל טוב סופג שינוי בלי להישבר — ומעצב טוב יודע איזו בקשה **לא** לקבל.
5. **הפרויקט נגמר כשמישהו אחר יכול להמשיך ממנו.** לא כשהתרשים יפה.
