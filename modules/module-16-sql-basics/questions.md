## 🟢 חלק א' — מושגים

### שאלה 1
**מה ההבדל בין שפה דקלרטיבית לשפה פרוצדורלית, ולאיזו מהן SQL שייכת?**

<details><summary>💡 תשובה</summary>

| | פרוצדורלית | דקלרטיבית |
|---|-----------|-----------|
| אומרים למחשב | **איך** לעשות | **מה** רוצים |
| דוגמה | "עבור על כל שורה, בדוק אם כלב, שמור" | `SELECT name FROM animal WHERE species_id = 1` |
| מי מחליט על הדרך | המתכנת | בסיס הנתונים |

**SQL דקלרטיבית.** זו בדיוק המהפכה של קוד (1970): המתכנת לא צריך לדעת איך הנתונים מאוחסנים כדי לשאול עליהם.

</details>

### שאלה 2
**מהם ארבעת החלקים של `SELECT` שנפגוש בקורס, ובאיזה סדר?**

<details><summary>💡 תשובה</summary>

| # | החלק | השאלה שהוא עונה עליה | המודול |
|---|-------|------------------------|---------|
| 1 | `SELECT` | **מה** להציג | 16 |
| 2 | `FROM` | **מאיפה** | 16 |
| 3 | `WHERE` | **אילו שורות** | 17 |
| 4 | `ORDER BY` | **באיזה סדר** | 18 |

**הסדר קבוע.** אפשר לדלג על חלקים, אבל מה שנשאר חייב להישאר בסדר הזה.

</details>

### שאלה 3
**"כל שאילתה מחזירה טבלה" — למה זה חשוב?**

<details><summary>💡 תשובה</summary>

שלוש סיבות:

1. **המקור לא משתנה.** `SELECT` יוצר טבלה **חדשה** (result set) — הטבלה המקורית נשארת כפי שהיא. `weight_kg * 2.2` מחשב לתצוגה בלבד.
2. **שורה אחת ועמודה אחת — עדיין טבלה.** `SELECT COUNT(*) FROM animal` מחזיר טבלה של 1×1.
3. ⭐ **אפשר לשאול טבלה.** ולכן אפשר לשים שאילתה **בתוך** שאילתה (מודול 24). זה עובד רק כי התוצאה היא טבלה.

</details>

### שאלה 4
**למה לא להשתמש ב‑`SELECT *` בקוד אמיתי?**

<details><summary>💡 תשובה</summary>

| הסיבה | ההסבר |
|--------|--------|
| **ביצועים** | טבלה עם 40 עמודות ו‑2 מיליון שורות — שולפים הכול, גם מה שלא צריך |
| **יציבות** | מוסיפים עמודה לטבלה ⟵ כל `SELECT *` בקוד משנה את התנהגותו בלי שאף אחד התכוון |
| **קריאוּת** | מי שקורא בעוד שנה לא יודע אילו עמודות באמת חשובות |

**`*` מצוין ללמידה** — "מה יש בטבלה הזאת?" — ורע לכל דבר אחר.

</details>

### שאלה 5
**מה ההבדל בין `'Luna'` לבין `"Luna"`?**

<details><summary>💡 תשובה</summary>

| | משמעות | דוגמה |
|---|--------|--------|
| `'Luna'` — גרש **בודד** | **ערך** טקסט | `WHERE name = 'Luna'` |
| `"Luna"` — גרש **כפול** | **שם** של עמודה/כינוי | `SELECT name AS "Animal Name"` |

⚠️ `SELECT "Luna" FROM animal` ⟵ בסיס הנתונים מחפש **עמודה בשם Luna**, ונכשל.

**זו הטעות הראשונה שכולם עושים.** הכלל: **בודד לערך, כפול לשם.**

</details>

### שאלה 6
**מה תעשה השאילתה הבאה, ומה חסר בה?**

</div>

```sql
SELECT first_name || last_name AS full_name
FROM   person;
```

<div dir="rtl">

<details><summary>💡 תשובה</summary>

היא תחבר שם פרטי ושם משפחה — **בלי רווח**: `RutiAlmog`, `NoaPeretz`.

**חסר:** `|| ' ' ||` באמצע.

</div>

```sql
SELECT first_name || ' ' || last_name AS full_name
FROM   person;
-- -> "Ruti Almog"
```

### שאלה 7
**מה ההבדל בתוצאה?**

</div>

```sql
SELECT status FROM animal;
SELECT DISTINCT status FROM animal;
```

<div dir="rtl">

<details><summary>💡 תשובה</summary>

| השאילתה | שורות | למה |
|----------|--------|------|
| בלי `DISTINCT` | **20** | שורה לכל חיה — `adopted` יופיע 8 פעמים |
| עם `DISTINCT` | **5** | כל ערך **פעם אחת**: `adopted`, `available`, `medical`, `quarantine`, `deceased` |

**ואם כותבים `SELECT DISTINCT species_id, status`?** — כל **צירוף** ייחודי של שניהם. `DISTINCT` חל על השורה כולה, לא על עמודה אחת.

</details>

## 🟡 חלק ג' — חישובים ו‑NULL

### שאלה 8
**מה יחזירו שתי השאילתות?**

</div>

```sql
SELECT 100 + 20 * 2;
SELECT (100 + 20) * 2;
```

<div dir="rtl">

<details><summary>💡 תשובה</summary>

| השאילתה | התוצאה | למה |
|----------|---------|------|
| `100 + 20 * 2` | **140** | כפל לפני חיבור: `20*2=40`, ואז `100+40` |
| `(100 + 20) * 2` | **240** | סוגריים קודם: `120`, ואז `*2` |

**סדר הפעולות כמו במתמטיקה.** בספק — סוגריים. הם לא עולים כלום ומונעים באגים.

</details>

---

### שאלה 9
**האם השאילתה משנה את הטבלה?**

</div>

```sql
SELECT name, weight_kg * 2 AS double_weight
FROM   animal;
```

<div dir="rtl">

<details><summary>💡 תשובה</summary>

**לא.** `SELECT` רק **קורא**. הוא מחשב `weight_kg * 2` ומציג את התוצאה — ב‑`animal` המשקל נשאר כפי שהיה.

**איך משנים באמת?** `UPDATE` — מודול 25. ועד אז: **אין שום שאילתה בקורס שמשנה נתונים.** אפשר לנסות הכול בלי לפחד.

</details>

### שאלה 10
**למה השורה של Mitzi ריקה לגמרי?**

</div>

```sql
SELECT name, 'Breed: ' || breed AS label
FROM   animal;
```

<div dir="rtl">

</div>

```text
name    label
------  ------------
Luna    Breed: Mixed
Mitzi                 <- ??
```

<div dir="rtl">

<details><summary>💡 תשובה</summary>

כי ל‑Mitzi אין גזע ידוע — `breed` שלה הוא **NULL**.

ו**כל פעולה עם NULL מחזירה NULL**: `'Breed: ' || NULL` = `NULL`. לא `"Breed: "` — כלום.

**למה?** NULL הוא "לא ידוע". "Breed: " ועוד "לא ידוע" — עדיין לא ידוע.

**הפתרון** במודול 20 (`COALESCE`). בינתיים — זה הדבר החשוב ביותר לדעת על NULL: **הוא מדביק.**

</details>

### שאלה 11
**מה ההבדל בין NULL, אפס ומחרוזת ריקה?**

<details><summary>💡 תשובה</summary>

| הערך | מה הוא אומר | דוגמה |
|-------|-------------|--------|
| `NULL` | **אין ערך / לא ידוע** | גזע לא ידוע · חיה בלי שבב |
| `0` | **הערך הוא אפס** — ידוע! | משקל 0 (לא הגיוני, אבל ידוע) |
| `''` | **מחרוזת ריקה** — ידוע! | שדה שמישהו מחק בכוונה |

**המבחן:** `0 + 5 = 5` · `'' || 'a' = 'a'` · `NULL + 5 = NULL`.
רק NULL "מדביק". השניים האחרים הם ערכים רגילים.

</details>

## 🔴 חלק ד' — קריאת שגיאות וסביבה

### שאלה 12
**מה השגיאה בכל אחת, בלי להריץ?**

</div>

```sql
-- a
SELECT nam FROM animal;
-- b
SELECT name, FROM animal;
-- c
SELECT name FROM animals;
-- d
SELECT 'Luna FROM animal;
```

<div dir="rtl">

<details><summary>💡 תשובה</summary>

| | השגיאה | ההודעה שתקבלו | התיקון |
|---|--------|---------------|---------|
| a | כתיב — `nam` | `no such column: nam` | `name` |
| b | פסיק לפני `FROM` | `near "FROM": syntax error` | הסירו את הפסיק |
| c | שם טבלה ברבים | `no such table: animals` | `animal` |
| d | גרש לא סגור | `unrecognized token` | `'Luna'` |

**הכלל:** המילה אחרי `near` מצביעה לאן בסיס הנתונים הגיע כשהתבלבל. הטעות היא **ממש לפניה**.

</details>

### שאלה 13
**למה הקורס משתמש ב‑Programiz ולא ב‑Oracle APEX, כמו תכנית הלימודים?**

<details><summary>💡 תשובה</summary>

| | Programiz | Oracle APEX |
|---|-----------|-------------|
| זמן עד לשאילתה ראשונה | 60 שניות | 10 דקות + הרשמה |
| שומר בין ביקורים | ❌ | ✅ |
| הדיאלקט | SQLite | Oracle |
| מתאים ל | **למידה ותרגול** | תכנית הלימודים הרשמית והבחינה |

**90% מהתחביר זהה.** ההבדלים (כמו `FROM DUAL`) מסומנים בכל מודול. מי שלמד כאן — עובר ל‑APEX בשעה.

**ההמלצה:** Programiz ללמידה, APEX לקראת הבחינה.

</details>

### שאלה 15
**מה ההבדל בין השאילתות, ואיזו נכונה?**

</div>

```sql
select name,weight_kg from animal;

SELECT name,
       weight_kg
FROM   animal;
```

<div dir="rtl">

<details><summary>💡 תשובה</summary>

**שתיהן זהות לבסיס הנתונים.** SQL לא רגיש לאותיות ולא לרווחים.

**אבל השנייה נכונה** — כי שאילתה נכתבת פעם אחת ונקראת עשרות פעמים.

**מוסכמות הקורס:**
- מילות מפתח באותיות **גדולות**
- שמות טבלאות ועמודות באותיות **קטנות**
- כל חלק בשורה משלו
- עמודות מיושרות
- `;` בסוף, תמיד

**הסיפור:** שאילתה של 400 מילים בשורה אחת, בלי הערה. כשהדוח יצא שגוי — שבועיים לפענח. **כתבו למי שיקרא.**

</details>

**מי שכותב הכול ומריץ פעם אחת** — מקבל שגיאה ולא יודע מאיפה להתחיל.
