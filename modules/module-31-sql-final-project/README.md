## 3. הסקריפט — מבנה מחייב

**`build.sql` חייב לרוץ מההתחלה עד הסוף, פעמיים ברצף, בלי שגיאה** — על מחשב שמעולם לא ראה את הפרויקט. זה המבחן הראשון שהמורה יריץ.

</div>

```sql
-- ============================================================
--  <Project name>  --  build script
--  Team: <names>            Date: <date>
--  Run this whole file. The last line must print the row counts.
-- ============================================================

PRAGMA foreign_keys = ON;

-- 1. DROP: children first, parents last  (module 26, section 7)
DROP VIEW  IF EXISTS ...;
DROP TABLE IF EXISTS order_item;
DROP TABLE IF EXISTS "order";
DROP TABLE IF EXISTS customer;

-- 2. CREATE: parents first, children last; named constraints; STRICT  (modules 26-27)
CREATE TABLE customer (
  customer_id INTEGER PRIMARY KEY AUTOINCREMENT,
  ...
  CONSTRAINT uq_customer_email UNIQUE (email)
) STRICT;
...

-- 3. INDEXES on every foreign key  (module 29)
CREATE INDEX idx_order_customer ON "order"(customer_id);
...

-- 4. VIEWS  (module 28)
CREATE VIEW ... AS ...;

-- 5. DATA  (module 25)  -- column lists, always
INSERT INTO customer (first_name, last_name, email, ...) VALUES (...), (...);
...

-- 6. CHECK: one row per table
SELECT 'customer' AS tbl, COUNT(*) AS n FROM customer
UNION ALL SELECT 'order', COUNT(*) FROM "order"
...;
```

<div dir="rtl">

> 🔑 **ההערות בסקריפט הן חלק מהציון.** מי שקורא צריך להבין **למה** כל אילוץ קיים: `-- business rule 4: a customer may have at most one active cart`.

## 4. נתוני דוגמה — כמה ואיך

| הכלל | למה |
|------|-----|
| **לפחות 8 שורות** בכל טבלה; 15+ בטבלאות המרכזיות | שאילתות `GROUP BY` צריכות קבוצות עם יותר משורה |
| **NULL אמיתי** בכל עמודה אופציונלית — בכמה שורות | אחרת אי אפשר להראות `LEFT JOIN`, `COALESCE`, `IS NULL` |
| **שורות "בלי התאמה"** — לקוח שלא הזמין, מוצר שלא נמכר | אחרת `LEFT JOIN … IS NULL` מחזיר תמיד ריק |
| **כפילות מכוונת אחת** (לקוח שהזמין פעמיים, כמו לונה) | בשביל `HAVING COUNT(*) > 1` |
| **שינוי לאורך זמן** (מחיר שעלה, סטטוס שהשתנה) | מודול 10 — להראות שההיסטוריה נשמרת |
| **תאריכים על פני שנתיים לפחות** | `GROUP BY` שנה / חודש |
| **נתונים הגיוניים** | לקוח בשם "aaa" עם הזמנה ב‑1900 — מפיל את כל המצגת |

> 💡 **בסיס הנתונים של המקלט הוא דוגמה לנתונים טובים:** לונה שנקלטה פעמיים, Coco בלי תאריך לידה, הוצאות בלי חיה, מחיר שהשתנה. **כל "מוזרות" בנתונים שם — היא שם בכוונה, כדי ששאילתה תוכל לגלות אותה.** עשו אותו דבר.

## 5. 15 השאילתות — רשימת חובה

כל שאילתה **מתחילה בשאלה של הלקוח במילים** — לא "JOIN של שלוש טבלאות", אלא "אילו לקוחות לא הזמינו כבר חצי שנה?".

| # | הסוג | המודול | דוגמה (בעולם של חנות) |
|---|------|---------|------------------------|
| 1 | סינון עם כמה תנאים ו‑`ORDER BY` | 17–18 | מוצרים במלאי, מתחת ל‑50 ₪, מהזול |
| 2 | פונקציות טקסט / תאריך | 19 | לקוחות שיש להם יום הולדת החודש |
| 3 | `CASE` + `COALESCE` | 20 | תווית לכל לקוח: "חדש" / "קבוע" / "רדום" |
| 4 | `JOIN` של 3 טבלאות או יותר | 21 | כל הזמנה עם שם הלקוח ושמות המוצרים |
| 5 | `LEFT JOIN … IS NULL` | 21–22 | מוצרים שמעולם לא נמכרו |
| 6 | self join **או** nonequijoin | 21 | זוגות לקוחות מאותה עיר / הנחה לפי מדרגת סכום |
| 7 | פונקציות מצרפיות + `SUM(CASE …)` | 23 | בשורה אחת: הכנסות לפי אמצעי תשלום |
| 8 | `GROUP BY` + `HAVING` | 24 | לקוחות שהזמינו יותר מ‑3 פעמים |
| 9 | `GROUP BY` לפי זמן (חודש / שנה) | 24 | הכנסות לפי חודש |
| 10 | תת‑שאילתה של ערך אחד | 24 | מוצרים יקרים מהממוצע |
| 11 | תת‑שאילתה מתואמת **או** `EXISTS` | 24 | המוצר הנמכר ביותר בכל קטגוריה |
| 12 | צבירה על צבירה (`FROM` / `WITH`) | 24 | ממוצע ההזמנות ללקוח |
| 13 | `UNION ALL` | 24 | ציר זמן: הזמנות והחזרות ברשימה אחת |
| 14 | שאילתה על **View** שלכם | 28 | `SELECT … FROM active_customer` |
| 15 | ⭐ השאלה **הכי חשובה** ללקוח | — | חופשי — זו שתפתח בה את המצגת |

> ⚠️ **שאילתה שמחזירה תוצאה ריקה** לא מוכיחה כלום. אם השאילתה נכונה אבל הנתונים לא מכילים מקרה כזה — **הוסיפו נתונים** (סעיף 4).

## 6. דוגמה מלאה — "שאילתות להנהלה" של המקלט

ככה נראות שאילתות טובות לפרויקט: שאלה, שאילתה, תוצאה, ו**מה זה אומר**. (על בסיס הנתונים המוכן, נכון ל‑`'2026-09-21'`.)

### שאלה: כמה זמן, בממוצע, חיה מחכה לבית — לפי מין?

</div>

```sql
-- for each species: available animals, and the average days since their LAST intake
SELECT s.name AS species,
       COUNT(*) AS waiting,
       ROUND(AVG(JULIANDAY('2026-09-21') - JULIANDAY(i.last_in)), 0) AS avg_days
FROM   animal a
JOIN   species s ON s.species_id = a.species_id
JOIN   (SELECT animal_id, MAX(intake_date) AS last_in      -- aggregate inside FROM (module 24)
        FROM intake GROUP BY animal_id) i ON i.animal_id = a.animal_id
WHERE  a.status = 'available'
GROUP  BY s.name
ORDER  BY avg_days DESC;
```

```text
species  waiting  avg_days
-------  -------  --------
Parrot   1        1087.0
Dog      3        877.0
Cat      4        876.0
Rabbit   1        578.0
```

<div dir="rtl">

> 📢 **מה זה אומר לרותי:** החיות הזמינות מחכות **בממוצע יותר משנתיים**. זו לא בעיה של מין מסוים — זו בעיה של המקלט כולו. **המלצה:** קמפיין אימוץ, מתחיל מהכלבים הוותיקים (Rocky — 1,220 יום).

### שאלה: כמה זמן לוקח לחיה להימצא בית — מהקליטה עד האימוץ?

</div>

```sql
SELECT a.name, i.intake_date, ad.adoption_date,
       CAST(JULIANDAY(ad.adoption_date) - JULIANDAY(i.intake_date) AS INTEGER) AS days
FROM   adoption ad
JOIN   animal a ON a.animal_id = ad.animal_id
JOIN   intake i ON i.animal_id = ad.animal_id
               AND i.intake_date = (SELECT MAX(i2.intake_date)          -- the intake just
                                    FROM   intake i2                     -- BEFORE this adoption
                                    WHERE  i2.animal_id   = ad.animal_id
                                      AND  i2.intake_date <= ad.adoption_date)
ORDER  BY days;
```

```text
name     intake_date  adoption_date  days
-------  -----------  -------------  ----
Luna     2023-03-14   2023-05-10     57
Simba    2023-04-02   2023-06-15     74
Kiwi     2024-10-12   2025-01-10     90
Charlie  2024-08-30   2024-12-01     93
Thumper  2024-02-14   2024-06-20     127
Zoe      2024-03-03   2024-08-15     165
Bella    2023-07-07   2024-02-10     218
Tom      2023-08-19   2024-05-05     260
Luna     2024-06-01   2025-07-01     395       <- the second time took 7 times longer
```

<div dir="rtl">

> 📢 **מה זה אומר:** לונה אומצה תוך חודשיים — אבל אחרי שהוחזרה, לקח לה **יותר משנה**. חיות שהוחזרו מתקשות יותר. **זו תובנה שרק תכנון נכון של `intake` (קליטה חדשה בכל חזרה — מודול 10) מאפשר לגלות.**
>
> 💡 **הטריק בשאילתה:** לונה נקלטה פעמיים ואומצה פעמיים. JOIN פשוט לפי `animal_id` היה נותן 4 צירופים. תת‑השאילתה המתואמת בוחרת לכל אימוץ את **הקליטה האחרונה שלפניו**.

### שאלה: מי המתנדבים הפעילים ביותר?

</div>

```sql
SELECT p.first_name || ' ' || p.last_name AS volunteer,
       COUNT(i.intake_id)                 AS animals_brought
FROM   person p
LEFT   JOIN intake i ON i.brought_by = p.person_id
WHERE  p.role = 'volunteer'
GROUP  BY p.person_id
ORDER  BY animals_brought DESC;
```

```text
volunteer    animals_brought
-----------  ---------------
Noa Peretz   5
Amir Levi    3
Tamar Golan  3
Ruti Almog   0          <- LEFT JOIN keeps her: Ruti manages, she doesn't do rescues
```

<div dir="rtl">

> 📢 **מה זה אומר:** נועה הביאה כמעט חצי מהחיות שחולצו. **שאלה ללקוח:** האם יש לה מספיק עזרה? מה קורה אם היא עוזבת?

**שימו לב למבנה של כל דוגמה:** שאלה במילים ⟵ שאילתה עם הערות ⟵ פלט אמיתי ⟵ **תובנה והמלצה**. החלק האחרון הוא ההבדל בין "כתבתי SQL" לבין "פתרתי בעיה ללקוח".

## 7. ההצגה — 10 דקות

(הכלים להכנת המצגת — במודול 15.)

| דקות | החלק | מה מראים |
|------|------|-----------|
| 1 | **הלקוח והבעיה** | מי הלקוח, מה כאב לו לפני |
| 2 | **העיצוב** | ה‑ERD — רק הישויות המרכזיות, ושתי החלטות עיצוב מעניינות |
| 4 | **הדגמה חיה** | מריצים `build.sql` ⟵ 3–4 שאילתות מרכזיות ⟵ מנסים להכניס נתון שגוי והאילוץ חוסם |
| 2 | **תובנות** | 2–3 דברים שהנתונים גילו, ומה ממליצים |
| 1 | **מה הלאה** | מה לא הספקתם, מה הייתם משנים |

> 🎬 **ההדגמה החיה היא לב המצגת.** "וזה מה שקורה כשמנסים לרשום הזמנה של לקוח שלא קיים" ⟵ `FOREIGN KEY constraint failed`. הקהל רואה שזה **עובד**. **אבל** — תרגלו אותה שלוש פעמים, והכינו צילומי מסך למקרה שהמחשב יקרוס.

## 8. מחוון הערכה

| הקריטריון | 100% | 70% | 40% |
|-----------|------|-----|-----|
| **סקריפט** (25%) | רץ פעמיים בלי שגיאה; `STRICT`; אינדקסים; הערות ברורות | רץ, אבל חסרים אינדקסים / הערות | נכשל, או צריך "לתקן משהו קטן" כדי שירוץ |
| **אילוצים** (10%) | כל חוק עסקי ממופה לאילוץ עם שם; קובץ בדיקה שמראה כל אחד נחסם | רוב החוקים ממופים | רק `PRIMARY KEY` ו‑`NOT NULL` |
| **שאילתות** (35%) | 15, כל סוג מהרשימה, כל אחת עם שאלה + פלט + תובנה | 15, אבל חלק בלי תובנה / חלק מחזירות ריק | פחות מ‑12, או סוגים חסרים |
| **ERD ועיצוב** (10%) | מנורמל (3NF), תואם לסקריפט אחד‑לאחד | פערים קטנים בין ERD לסקריפט | ERD ישן שלא תואם |
| **הצגה** (20%) | בזמן, הדגמה חיה עובדת, תובנות עסקיות, עונים על שאלות | בזמן, הדגמה עם תקלות | קריאה מהשקפים, בלי הדגמה |

## 10. רשימת בדיקה לפני הגשה

| ✔ | הבדיקה |
|---|--------|
| ☐ | `build.sql` רץ **פעמיים ברצף** על חלון ריק ב‑Programiz / DB Browser — בלי שגיאה |
| ☐ | `PRAGMA foreign_keys = ON;` בשורה הראשונה |
| ☐ | לכל טבלה `PRIMARY KEY`; לכל מפתח זר — `REFERENCES` ו‑אינדקס |
| ☐ | לכל אילוץ שם (`pk_`, `fk_`, `uq_`, `chk_`) |
| ☐ | בכל טבלה לפחות 8 שורות; יש NULL‑ים, שורות בלי התאמה, וכפילות מכוונת |
