# 🐾 הפרויקט המלווה — מקלט לבעלי חיים

> פרויקט זה מלווה את הקורס מתחילתו ועד סופו. בכל מודול נוסיף לו שכבה, עד שנגיע למערכת מלאה עם טבלאות ושאילתות SQL אמיתיות.
>
> **מקור:** הפרויקט מבוסס על **פרק 9** בתכנית הלימודים — "פרויקט I: מקלט לבעלי חיים".

---

## 📋 תיאור הלקוח

> *"אנחנו מקלט לבעלי חיים. אנשים מביאים אלינו חיות — כלבים, חתולים, לפעמים ארנבים ותוכים. חלקן נמצאות ברחוב על ידי המתנדבים שלנו, חלקן נמסרות על ידי בעלים שלא יכולים להמשיך לגדל אותן.*
>
> *כל חיה עוברת בדיקה וטרינרית בכניסה, ומקבלת חיסונים לפי הצורך. אנחנו מחפשים לה בית מאמץ. מאמצים פוטנציאליים ממלאים טופס, אנחנו מראיינים אותם, ואם הם מתאימים — הם מאמצים. אחרי אימוץ אנחנו עושים ביקורת בית אחרי חודש.*
>
> *יש לנו 12 מתנדבים ו‑2 וטרינרים. אנחנו רוצים לדעת כמה זמן כל חיה שוהה אצלנו בממוצע, וכמה עולה לנו להחזיק אותה."*
>
> — **רותי**, מנהלת המקלט

## 🎯 מצב הפרויקט כרגע — סוף מודול 5

### הישויות שזוהו

| הישות | תיאור |
|-------|--------|
| `ANIMAL` | החיה — עם טיפוסי משנה: `DOG`, `CAT`, `RABBIT`, `PARROT`, `OTHER` |
| `SPECIES` | קטלוג המינים |
| `INTAKE` | קליטה — עם טיפוסי משנה: `STRAY_INTAKE`, `SURRENDER_INTAKE` |
| `PERSON` | כל אדם במערכת — עם תפקידים |
| `ROLE` / `PERSON_ROLE` | תפקידים: מתנדב, מאמץ, בעלים קודם, וטרינר |
| `VET_DETAILS` / `VOLUNTEER_DETAILS` | פרטים ייחודיים לתפקיד |
| `VET_EXAM` | בדיקה וטרינרית |
| `VACCINATION` / `VACCINE_TYPE` | חיסונים |
| `ADOPTION_APPLICATION` | בקשת אימוץ + ראיון |
| `ADOPTION` | האימוץ עצמו |
| `HOME_VISIT` | ביקורת בית |
| `EXPENSE` | הוצאות על חיה |

### החלטות העיצוב המרכזיות

| # | ההחלטה | הנימוק |
|---|---------|---------|
| 1 | **`PERSON` אחד עם תפקידים**, ולא ישויות נפרדות | אדם יכול להיות גם מתנדב וגם מאמץ — מודל טיפוסי משנה היה מפר את כלל הבלעדיות |
| 2 | **טיפוסי משנה לחיה** (כלב/חתול/ארנב/תוכי) | לכל מין מאפיינים, יחסים וחוקי אימוץ שונים |
| 3 | **מימוש בשיטה ג'** — טבלת על + טבלה לכל משנה | חמש ישויות צריכות להצביע על "חיה כללית" |
| 4 | **`INTAKE` כטיפוסי משנה ולא כקשת** | לכל סוג קליטה 4–5 מאפיינים ייחודיים |
| 5 | **יחס רקורסיבי ב‑`ANIMAL`** (אמא ⟵ גורים) | המקלט מטפל בהמלטות |
| 6 | **שום דבר לא נמחק** | היסטוריה רפואית ומשפטית |
| 7 | **רוב היחסים סומנו כלא עבירים** (◇) | אירועים רפואיים ומסמכי אימוץ אינם ניתנים להזזה |
| 8 | **מזהים מלאכותיים לכל הישויות המקשרות** | אותו אדם יכול לאמץ את אותה חיה פעמיים; חיסון חוזר מדי שנה |
| 9 | **`VACCINATION` אינו יחס טרנרי** | הווטרינר הוא מאפיין של האירוע, לא צלע שלישית |

## 📝 איך לעבוד על הפרויקט

1. **פתרו לבד תחילה.** בכל מודול, התרגיל האחרון הוא שלב בפרויקט — פתרו אותו לפני שאתם פותחים את הפתרון.
2. **שמרו את העבודה שלכם.** צרו תיקייה משלכם והוסיפו את התרשימים והמסמכים שלכם.
3. **השוו — אל תעתיקו.** הפתרון המוצע הוא **אחד** מכמה פתרונות תקינים. אם שלכם שונה — בדקו אם הוא **מנומק**, לא אם הוא זהה.
4. **תעדו את ההנמקות.** בעיצוב בסיסי נתונים, ההנמקה חשובה יותר מהתוצאה.
